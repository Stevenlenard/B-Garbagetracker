# Safe commit and push of `fix/priority1-gps-sync`

NOT EXECUTED. Run the blocks yourself, in order, from `C:\Projects\B-Garbagetracker`.
Do not use `git add .` or `git add -A`: the working tree also contains files that must
not be committed (see "Left out on purpose").

## 0. Check where you are
```bash
git branch --show-current          # must print: fix/priority1-gps-sync
git status --short | head -100
```

## 1. Stop tracking the database dumps (recommended, new commit only)
`backend/backups/` holds 48 `.sql` dumps (user rows with password hashes). They are
already in `origin/main` history; this only stops tracking them from now on and keeps
your local copies.
```bash
git rm -r --cached backend/backups
```
`.gitignore` already lists `/backend/backups/` so they will not be re-added.
(Removing them from history needs a history rewrite and coordination with your team;
rotate the credentials either way.)

## 2. Stage ONLY the intended files
```bash
git add -- .gitignore pubspec.lock android/app/src/debug/AndroidManifest.xml

git add -- backend/approve_user.php backend/reject_user.php backend/register.php \
           backend/login.php backend/verify_otp.php backend/file_complaint.php \
           backend/update_complaint.php backend/save_trip_history.php backend/auth_token.php

git add -- lib/ test/ deploy_prep/
```
`lib/`, `test/` and `deploy_prep/` contain only intended files (listed below); `build/`
is ignored.

## 3. Verify what is staged (read this before committing)
```bash
git status --short
git diff --cached --stat | tail -5
# nothing secret-looking may appear in the staged diff (values are not printed):
git diff --cached | grep -n -i -E "BEGIN [A-Z ]*PRIVATE KEY|client_secret|sk\.eyJ|ghp_|AKIA" || echo "no matches"
# these must NOT be staged:
git diff --cached --name-only | grep -E "^(backend/db_config|backend/email_config|backend/auth_config|backend/approval_config|android/local|CAPSTONE_SYSTEM_AUDIT|linux/)" && echo "STOP: unexpected file staged" || echo "ok"
```

## 4. Commit
```bash
git commit -m "Priority 1: real-time GPS sync, automatic driver lifecycle, shared fleet policy, account and complaint fixes

- Driver: automatic trip at login, FULL freezes the collection record, COMPLETED
  confirms unloading, session ownership, no zombie writes.
- Admin/Resident: shared fleet snapshot, incremental truck feed, aging tick,
  driver/truck marker labels, per-trip route binding.
- Backend: registration/approval/login hardening, complaint validation and resolution,
  trip-history freeze, optional token authorization (off by default).
- Tests: Flutter unit tests and a PHP backend regression harness.
- deploy_prep: rollout, SQL inspection/repair/rollback, Firebase rule drafts.

Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>"
```

## 5. Push the branch (not main)
```bash
git push -u origin fix/priority1-gps-sync
```
Open a pull request into `main` rather than pushing to `main` directly.

## What your friend needs to build the Android APK
1. `git fetch && git switch fix/priority1-gps-sync`
2. Flutter 3.47.x stable (this was built with 3.47.6), Android SDK + the NDK that
   Flutter selects (28.2.13676358 on the original machine: install via the SDK manager).
3. `flutter pub get` then `flutter build apk --release`.
No secret files are required: Firebase options, the public Mapbox token and the PHP base
URL are in source (`lib/main.dart`, `lib/api/api_client.dart`). The release build is
signed with the DEBUG key (`android/app/build.gradle.kts`), so it will not update an app
signed with another key.
